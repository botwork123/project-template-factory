# Prefect + Docker Blueprint for Python Template

## Goal
Make new Python projects generated by this template immediately deployable via Prefect using image-based execution (no source bind-mount runtime).

## Non-negotiables
- Same settings contract in dev and deployed runs
- Single source of truth for config keys
- `.env.example` auto-generated from settings schema
- Prefect workers execute project image, not local source checkout

## Proposed Template Additions

### 1) Runtime settings contract (single source of truth)
Add `src/__PROJECT_NAME__/settings.py`:
- Pydantic settings model (or equivalent typed schema)
- Required env keys + defaults
- `validate_startup()` helper
- `generate_env_example()` helper (writes `.env.example`)

Add script `scripts/generate_env_example.py`:
- imports settings schema
- regenerates `.env.example`

### 2) Docker packaging (first-class)
Add to template root:
- `Dockerfile`
- `.dockerignore`
- `docker-compose.yml` (local app run)

Principle:
- dev local run and container run call same app entrypoint + settings loader

### 3) Prefect scaffolding (image-based)
Add `prefect.yaml` template with:
- work pool + queue placeholders
- deployment entrypoint placeholders
- image placeholder `registry/__PROJECT_NAME__:${IMAGE_TAG}`

Add `scripts/prefect/deploy.sh`:
- expects image tag and API URL
- runs `prefect deploy` against generated `prefect.yaml`

### 4) CI integration
Update template CI workflow to include:
- build container image smoke
- run `scripts/generate_env_example.py` and fail if diff exists
- optional deployment metadata lint (no live server required)

### 5) Docs and guardrails
Add `docs/deployment.md` in template:
- local dev flow
- build/push image flow
- Prefect deploy flow
- required env keys handling via settings schema

Add `Makefile` targets (or scripts) in template:
- `make env-example`
- `make docker-build`
- `make prefect-deploy`

## Rollout Plan
1. Add base scaffolding to template
2. Add tests for env-example generation + settings validation
3. Add generator smoke asserting new files exist in generated projects
4. Validate by generating a test project and running:
   - local app start
   - docker build
   - env-example generation check

## Acceptance Criteria
- Fresh generated Python project contains Docker + Prefect scaffolding
- `.env.example` is generated from schema, not manually edited
- Dev and containerized runtime import the same settings module
- No path requiring source bind mounts in worker runtime
